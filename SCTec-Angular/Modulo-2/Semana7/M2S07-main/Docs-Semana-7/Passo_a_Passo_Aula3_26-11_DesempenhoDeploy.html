Testar: antes da parte A, o console mostra estaInscrito() chamado: 6, 12, 24.... Depois, o contador some. Com o preloading, abra F12 → Network → JS: os chunks das outras páginas são baixados logo após abrir o site.

Meça o efeitoPreloading deixa a navegação instantânea, mas faz o celular trabalhar mais logo após abrir. Na nossa medição (celular simulado com 4G lento), o TBT subiu de ~440 ms para ~600 ms. Em projetos reais, decida medindo o seu público.

Etapa E · Deploy no Firebase Hosting (caminho principal)

ComandoO que faz / como responder
npm install -g firebase-toolsInstala a CLI do Firebase (uma vez por computador). Sem permissão? Use npx firebase-tools no lugar de firebase em todos os comandos.
firebase loginAbre o navegador para entrar com a sua conta Google.
firebase init hostingCreate a new project → nome único (ex.: sctec-seunome) · public directory: dist/projeto-angular-sctec/browser · single-page app: Yes · GitHub: No · overwrite index.html: No
ng buildGarante que a pasta publicada está atualizada.
firebase deployPublica. No fim aparece Hosting URL: https://sctec-seunome.web.app.
Cuidado na pergunta "Overwrite index.html?"Responda No. Se respondeu Yes, o site mostra "Welcome to Firebase Hosting": rode ng build e firebase deploy de novo.

Plano B · Netlify Drop

  1. Rode ng build e confira que dist/projeto-angular-sctec/browser/_redirects existe (veio da pasta public).
  2. Acesse app.netlify.com/drop, entre com GitHub ou e-mail e arraste a pasta browser.
  3. Em segundos aparece a URL https://nome-aleatorio.netlify.app (dá para renomear em Site configuration).

Como saber se deu certo (checklist do deploy)

  • A URL pública abre o portal; o rodapé mostra ambiente: produção.
  • Abrir /cursos direto na barra e apertar F5 em /inscricoes funciona (rewrite).
  • Login com emilys funciona no site publicado.
  • Lighthouse (F12 → Lighthouse) rodado na URL publicada: anote as 4 notas.
  • URL colocada no README.md do projeto · git commit -m "feat(deploy): desempenho e publicacao" · git push.
